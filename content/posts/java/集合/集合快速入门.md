# 两大基本接口
目前的 java 集合主要继承自两大接口: **Collection** 和 **Map**

为什么要这样设计呢?
我个人理解是: 存储的数据分为两种: 一种是一组数据,另一种是键值对
这两种方式所需的方法完全不同,于是就分成了两种

以下是基本的方法:
```
Collection接口:
 - size() 长度
 - add() 直接向集合里面添加元素
 - remove() 删除元素
 - contains() 是否包含元素

 Map接口:
 - size() 长度
 - get() 获取元素
 - put() 放置元素
 - containsKey() 是否包含键
 - containsValue() 是否包含值
```

# Collection
## Iterable接口
为了方便遍历集合,Collection继承了Iterable<T>接口
该接口代表"可以产生迭代器的对象",提供便利工具**Iterator**
```
public interface Iterable<T> {
    Iterator<T> iterator();

    default void forEach(Consumer<? super T> action) {
        Objects.requireNonNull(action);

        for(T t : this) {
            action.accept(t);
        }

    }

    default Spliterator<T> spliterator() {
        return Spliterators.spliteratorUnknownSize(this.iterator(), 0);
    }
}
```
三个方法
- iterator() 用于提供遍历工具
- forEach() 出现于java8,是服务于函数式便利,这里不细说
- spliterator() 提供“可拆分的迭代器” 同样服务于Stream流

### Iterator<E>接口
```
public interface Iterator<E> {
    boolean hasNext();

    E next();

    default void remove() {
        throw new UnsupportedOperationException("remove");
    }

    default void forEachRemaining(Consumer<? super E> action) {
        Objects.requireNonNull(action);

        while(this.hasNext()) {
            action.accept(this.next());
        }

    }
}
```
